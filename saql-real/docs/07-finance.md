## 7.2 الموازنة العامة (المعالج)

### الحقول (`program_budget_version`)

| الحقل | معناه | الافتراضي المقترح في المعالج (ليس إلزامياً) |
|---|---|---|
| `focus` {mode, per_item, total, divisor} | مرصود لقاء التركيز العادي | per_item 150 (أو total 1000 ÷ 16) |
| `umrah_per_group` | مرصود لقاء العمرة لكل مجموعة | 1,500 |
| `internal_trip` | مرصود الرحلة الداخلية | 3,500 (أو total ÷ عدد الرحلات) |
| `external_trip` | مرصود الرحلة الخارجية | 15,000 |
| `opening` / `closing` | الافتتاحي / الختامي | 4,000 / 20,000 |
| `meeting_default` | مرصود الاجتماع الواحد | 300 (الديمو يترك الاجتماعات بلا مرصود في المعالج؛ التجربة 300) |
| `program_needs` | مرصود احتياجات البرنامج (إجمالي) | 15,000 |
| `focus_min`, `focus_max` | لقاءات التركيز بميزانية لكل مجموعة | 4 و8 |

### خطوات المعالج (BR-505)
1. **لقاءات التركيز**: مبلغ لكل لقاء، أو إجمالي ÷ مقسوم عليه (الافتراضي = عدد المجموعات × الحد الأدنى = 16) يُعرض ناتج القسمة قبل الحفظ؛ ومعه حدّا 4 و8.
2. **لقاء العمرة**: مبلغ لكل مجموعة.
3. **الرحلات الداخلية** و4. **الخارجية**: لكل رحلة، أو إجمالي ÷ عدد رحلات ذلك النوع.
5. **الافتتاحي** و**الختامي**.
6. **الاجتماعات**: مرصود اختياري.
7. **مراجعة وحفظ** ← يُنشأ `version=1` وتُقفل (BR-530). قبل ذلك: «لا تُقبل طلبات».

### قاعدة التقسيم (دقيقة)
```
perItem(rule) = rule.mode == 'per_item' ? rule.per_item
              : rule.divisor > 0 ? round(rule.total / rule.divisor, 2) : 0
defaultDivisor(focus)         = count(groups) * focus_min          -- 4×4 = 16
defaultDivisor(internal_trip) = count(trips WHERE type='internal') -- كل الداخلية (بما فيها رحلات فريق العمل)
```
مثال: إجمالي لقاءات التركيز 2,400 ÷ 16 = **150.00**. إجمالي 1,000 ÷ 16 = 62.50.

### المرصود لعنصر (`allocated_for`) — BR-507
| العنصر | المرصود |
|---|---|
| لقاء تركيز عادي (`seq_in_group ≤ focus_max`) | `perItem(focus)` |
| لقاء العمرة (`seq ≤ max`) | `umrah_per_group` |
| لقاء تركيز `seq > focus_max` | **0** ← لا يُطلب له (BR-303) |
| اجتماع | `meeting.allocated ?? meeting_default` |
| احتياج برنامج | 0 (مرصوده إجمالي `program_needs`) |
| افتتاحي / ختامي | `opening` / `closing` |
| رحلة | `perItem(internal_trip|external_trip)` |

### نظرة الموازنة (`budget_overview`)
لكل نوع (رحلات داخلية، خارجية، لقاءات التركيز، العمرة، افتتاحي، ختامي، اجتماعات، احتياجات): `allocated` (المرصود الكلي = مرصود الوحدة × عدد الوحدات؛ أو الإجمالي إن `total`)، `approved` (مجموع طلبات معتمدة + العهد بلا طلب)، `spent` (المقبول من العهد + الصرف المباشر الموزّع + دفعات العقود المدفوعة). الإجمالي = مجموع الأسطر. العمرة تُفصل عن التركيز بـ`is_umrah`.

## 7.3 التصنيفات والبنود

الافتراضية (يضيفها مسؤول المالية ويعدّلها): المواصلات (حافلة، سيارات وتوصيل، وقود) · التغذية (وجبات رئيسية، وجبات خفيفة) · السكن (سكن المدربين، سكن المشاركين) · الضيافة (قهوة وتمر، ماء ومشروبات) · مكافآت الضيوف (محاضر، مدرب ورشة) · تذاكر ودخول (رسوم دخول) · أدوات ومطبوعات (مطبوعات، دروع وهدايا) · أخرى.
تُستخدم في: الموازنة التفصيلية، نماذج الصرف، الصرف المباشر، التحليل. **لا حذف** لمستخدم (BR-528). دفعات العقود تُصنَّف في التحليل تحت اسم «العقود».

## 7.4 طلب الميزانية

| الحقل | قاعدة |
|---|---|
| المالك `(owner_kind, owner_id)` | رحلة / لقاء تركيز / اجتماع / حدث (افتتاحي/ختامي). `need` غير مسموح بطلب (BR: يُصرف مباشرة أو بعهدة) |
| المبلغ | = مجموع الأسطر إن تفصيلية، وإلا مدخل >0 |
| الأسطر | تصنيف + بند + وصف + وحدة + كمية + سعر (`qty×price`) |
| المرصود `allocated` | يُلتقط وقت الإرسال |
| السجل | `budget_request_event` لكل إجراء |

### جدول المسار

| الحالة المستهدفة | الشرط |
|---|---|
| `pending_facilitator` | `owner_kind=trip` ∧ رحلة مجموعة |
| `pending_leader` | رحلة فريق عمل ∨ (غير الرحلة ∧ `amount > allocated`) ∨ بعد `needs_detail` |
| `pending_finance` | غير الرحلة ∧ `amount ≤ allocated` |

**التنبيه:** ق.ع يُنبَّه في الإشعار وفي شاشة القرار حين `amount > allocated` (س6). اعتماده لميزانية رحلة لا يعني الصرف: يُشعَر من يملك `disburse` «حوّل العهدة».

مثال: طلب لقاء تركيز 140 ر.س والمرصود 150 ← `pending_finance`. طلب عمرة 1,860 والمرصود 1,500 ← `pending_leader` («يتجاوز المرصود»). طلب ضيف خارجي 400 لقاء تركيز والمرصود 150 ← ق.ع يرفضه بسبب «مكافأة الضيف لا تُصرف من لقاءات التركيز».

## 7.5 المحفظة (دفتر مسؤول المالية)

| الحركة | الاتجاه | المرفق | ينشئها |
|---|---|---|---|
| `deposit` إيداع | داخل | إيصال حوالة + الجهة المحوِّلة | `disburse` |
| `surplus_return` فائض عهدة | داخل | إيصال تحويل المستلم | عند تسوية الفائض |
| `custody_transfer` تحويل عهدة | خارج | إيصال التحويل | صرف العهدة/دفعاتها |
| `direct_spend` صرف مباشر | خارج | فاتورة/إيصال تحويل | `disburse` |
| `contract_payment` دفعة عقد | خارج | فاتورة الدفعة/إيصالها | `disburse` |
| `deficit_payout` تحويل عجز | خارج | إيصال تحويل العجز | عند تسوية العجز بالتحويل |

```
balance = Σ(deposit + surplus_return) − Σ(custody_transfer + direct_spend + contract_payment + deficit_payout)
```
**ثوابت (تُختبر):** (1) كل حركة لها `attachment_id` (2) `amount > 0` (3) لا حركة تجعل الرصيد < 0 (قفل صف `wallet_lock` داخل transaction) (4) الحركة لا تُعدَّل/تُحذف (BR-533) (5) كل حركة خارجة مرتبطة بسجل مرجعي (تحويل عهدة / صرف مباشر / دفعة / تسوية).
رسالة الرصيد: «الرصيد الفعلي X لا يكفي لـ Y. سجّل إيداعاً، أو اصرف جزءاً وأجّل الباقي.»

## 7.6 العهدة

- **الدورة:** طلب معتمد ← `disburse` (مبلغ التحويل الأول ≤ المعتمد، ويُقبل جزء لضعف الرصيد) ← `transferMore` للباقي ← نماذج الصرف ← طلب إغلاق ← مراجعة ← تسوية ← إغلاق.
- **لا آيبان ولا تأكيد استلام** (A#118، يلغي نص التصور 11.6): التحويل بإيصال يعبّئ رصيد المستلم مباشرة. بيانات المستلم البنكية (آيبان وباركود) من ملفه الشخصي وتظهر لمسؤول المالية في نافذة التحويل فقط.
- **عهدة بلا طلب:** افتتاحي، ختامي، احتياجات البرنامج (لشخص يقفلها مثل ق.ع).
- **قاعدة العهد المتزامنة (BR-517):**
```
open = custodies WHERE recipient_id = :r AND status <> 'closed'
تعارض إن: ∃ c ∈ open: family(c.spend_kind) = family(:kind)      -- trips = {internal_trip, external_trip}
        أو |open| ≥ settings.finance.max_open_custodies (2)
```
- **أرقام العهدة** (انظر 5.4). `available` قد تكون سالبة وهذا مسموح (عجز).

## 7.7 نموذج الصرف ومراجعة الفواتير

### الرفع (المستلم)
`vendor` (مطلوب) · `invoice_date` · `proof_kind` · صورة (إلزامية) · `serial` (اختياري) · أسطر: (تصنيف **أو** «غير موجود» + اسم مقترح) + شرح حر + مبلغ. التطابق مع إجمالي مكتوب **غير مطلوب** (A#122: مجموع الأسطر هو الإجمالي؛ هذا يخالف نص التصور 11.7 الذي منع الإرسال عند اختلاف الأسطر عن الإجمالي).
يُحجز مبلغ السطر (`pending`) من رصيد العهدة. تُحسب التحذيرات وتصل للمراجعين.

### المراجعة (م.م/مفوَّض، ليس المالك)
جدول واحد لكل البنود (صف لكل سطر، مجمَّع بالنموذج)، الفلتر الافتراضي «بانتظار»؛ رأس المجموعة: النشاط، صاحب العهدة، مجموع النموذج، رصيد العهدة، المتاح بعد المحجوز. التعديل من الصف: التصنيف والمبلغ فقط، وسطر «عدّلته المالية: كان…». لا اعتماد جماعي (جرد الشاشات).

```
accept(line):  require form.serial ≠ null
               require resolved category_id
               require amount > 0
               if category/amount changed: store original_*
               line.status = accepted  (locked)
reject(line):  require note
```
بند «غير موجود» لا يُقبل قبل ربطه بتصنيف موجود.

### التكرار والتجزئة (BR-521/522)
```
duplicates(p) = ⋃ { o ∈ allProofs, o.id ≠ p.id :
     o.hash = p.hash                                          → "الصورة نفسها"
  or (p.serial ∧ o.serial ∧ norm(o.serial)=norm(p.serial) ∧ norm(o.vendor)=norm(p.vendor)) → "الرقم+المورد"
  or (norm(o.vendor)=norm(p.vendor) ∧ |o.amount−p.amount|<0.01 ∧ o.invoice_date=p.invoice_date) → "المورد+المبلغ+التاريخ" }
split(f) = (sum(original amounts of f) ≤ maxAmount)
         ∧ |{ x : same activity ∧ same vendor ∧ small(x) ∧ |x.date − f.date| ≤ windowDays }| ≥ minCount
```
المبلغ المقارَن = **المبلغ الأصلي المرفوع** (قبل تعديل المالية). مصادر المقارنة: نماذج الصرف + الصرف المباشر + دفعات العقود المدفوعة.
الحقيقية تضيف **[جديد]**: فهرس على `file.sha256` و`lower(trim(vendor))` لجعل الكشف استعلاماً فهرسياً، وحقل `ocr_serial` لاحقاً (مكان `readSerial` في الديمو يعيد فارغاً).

## 7.8 الإغلاق المالي

1. المستلم: **طلب الإغلاق** (يوقف الصرف فوراً).
2. تُراجَع كل البنود (`pendingLines = 0`).
3. يصل م.م/المفوَّض جدول واحد: كل البنود المعتمدة وفواتيرها وفي آخره الفائض أو العجز.
4. **فائض** (`balance > 0`): المستلم يحوّله لحساب م.م ويرفع إيصاله ← `settle` يؤكد ويُنشئ `surplus_return` في المحفظة.
5. **عجز** (`balance < 0`): يختار المفوَّض (أ) **تحويلاً** للشخص من المحفظة بإيصال ← `deficit_payout`، أو (ب) **تسوية خارجية** يتحمّلها م.م أو صاحب العهدة بمستند إقرار/إيصال (إلزامي). 
6. `closeCustody` عند تحقق `custodyCloseChecks`.

مثال أرقام: معتمد 3,240، محوَّل 3,240، مقبول 3,160 ⇒ فائض **80** (يعيده المستلم بإيصال). مثال العجز: محوَّل 3,240، مقبول 3,300 ⇒ عجز **60** ← تسوية خارجية يتحمّلها صاحب العهدة بمستند «إقرار تسوية».
**الإغلاق المالي للرحلة** = إغلاق **كل** عهدها؛ ويُحسب موعده من آخر عهدة أُقفلت (BR-611).

## 7.9 الصرف المباشر والعقود والاحتياجات

- **الصرف المباشر**: م.م/`disburse` يصرف من المحفظة على نشاط أو أكثر، بفاتورة إلزامية وتصنيف ومبلغ، بلا اعتماد ولو تجاوز المرصود. تُربط الحصص بالأنشطة (`direct_spend_allocation`) ويشترط:
```
Σ allocation.amount = Σ line.amount = total      -- بالضبط
wallet_balance ≥ total
```
يظهر مع العهدة في إغلاق النشاط: **إجمالي المصروفات = العهدة المقبولة + المباشر (حصة النشاط)**. المصروف المشترك في المزدوجة (السكن) يوزَّع على الجزأين بمبلغ (أو نسبة تُحوَّل لمبلغ قبل الحفظ) ويُرفق مرة واحدة.
- **احتياجات البرنامج**: بنود (`program_need`) يُصرف عليها مباشرة أو بعهدة لشخص يقفلها أو بعقد.
- **العقد**: `contract(total)` و`contract_payment(amount, due_date)`؛ `Σ amounts = total`؛ تُدفع كل دفعة بإيصال/فاتورة ورصيد كافٍ؛ تظهر دفعات الموعد القريب لتذكير م.م.
- **الافتتاحي والختامي**: حدثان (`program_event`) واحد لكل نوع، يجوز إنشاؤهما بأثر رجعي منتهيَين، ويقبلان صرفاً مباشراً أو عهدة.

## 7.11 الرسوم

`fee_record` لكل مشارك: `amount` (الافتراضي `feeAmount` 500)، الحالة، `paid_amount`، `exemption` نصي حر (يُحوّل الحالة إلى مسدد ولا يدخل المحصَّل). **تسجيل فقط** بلا مرفق (لأنها ليست إيداعاً في المحفظة)، والدفع داخل المنصة إعداد `feesInPlatform` غير مفعّل. فرق: المحصَّل = Σ المبالغ المدفوعة فعلاً (بدون الاستثناءات).

## 7.12 التدقيق (`audit_log`)

أحداث مالية تُسجَّل بـ`area='finance'`: إعداد الموازنة · تعديل الإعدادات المالية · منح/سحب صلاحية · إضافة تصنيف · إيداع · موافقة/رفض طلب · اعتماد ق.ع (مع «تتجاوز المرصود») · صرف عهدة · تحويل دفعة · قبول/رفض بند · صرف مباشر · عقد · دفعة عقد · استلام فائض · تحويل عجز · تسوية خارجية · إغلاق عهدة · تحديث رسوم · طلب/قرار تعديل · مرصود اجتماع. كل سطر: من، متى، ما حدث، المرجع، قبل/بعد. يظهر سجل المالية في «التقارير» ولـم.م والمفوَّض؛ وسجل الأدوار/الحسابات/الإعدادات لـم.ت وق.ع.

## 7.13 سلامة الأرقام (إلزامي)

| الخطر | الإجراء في الحقيقية |
|---|---|
| أخطاء الفاصلة العائمة | `numeric(12,2)`؛ لا `number` JS للمال: تُخزَّن في الذاكرة كأعداد صحيحة بالهللة (`bigint`) أو مكتبة عشرية (`decimal.js`)؛ API يرسل المبالغ **نصاً** `"3240.00"` |
| سباق السحب المتزامن من المحفظة | `SELECT ... FOR UPDATE` على `wallet_lock` أو قيد trigger يحسب الرصيد داخل transaction |
| تحويل مكرر (ضغطتان) | `Idempotency-Key` + `UNIQUE(custody_transfer.wallet_entry_id)` (BR-536) |
| تعديل بعد الإغلاق | سطور المراجَعة وسجلات المحفظة والتدقيق read-only بـtriggers وصلاحيات DB (BR-533)؛ العهدة `closed` ترفض أي إدراج نموذج/تحويل |
| مبالغ سالبة/صفرية | `CHECK (amount > 0)` على الحركات والأسطر |
| عدم تطابق التوزيع/العقد | triggers مؤجَّلة (`DEFERRABLE INITIALLY DEFERRED`) تفحص التساوي التام عند COMMIT |
| تغيّر المرصود بعد التقديم | `allocated` + `allocated_version` مخزّنان في الطلب |
| سباق مراجعة السطر | تحديث شرطي `WHERE status='pending'` |
| تسوية تتم مرتين | `custody_settlement.custody_id` PK |
| فقدان الإثبات | `attachment_id NOT NULL` + ملفات لا تُحذف فعلياً (`deleted_at` فقط وبموافقة) |
| تطابق الأرقام | مهمة ليلية `reconcile`: `Σ wallet` = إيداعات − ... ، وكل `custody.transferred = Σ custody_transfer`، وكل `direct_spend.total = Σ allocations` — تُنبّه م.م/م.ت عند أي فرق |

### ثوابت تُختبر آلياً (Property tests)
1. `wallet_balance ≥ 0` بعد أي تسلسل عمليات.
2. `Σ custody_transfer(c) ≤ c.approved`.
3. `custody.transferred − accepted = surplus − deficit`.
4. لا يُقبل سطر دون `serial` ودون `category_id`.
5. لا يوافق مستخدم على طلبه ولا يراجع بنود عهدته.
6. `Σ direct allocations = invoice total` دائماً.
7. تعديل الموازنة لا يغيّر `allocated` لطلب قائم.

## 7.14 مثال كامل (رحلة داخلية)

1. ق.ع ينشئ «رحلة قُباء» لمجموعة `g2`. المرصود 3,500.
2. ق.م يرفع الوثيقة ثم الجدول ثم **طلب الميزانية**: 5 أسطر مجموعها 3,240 (≤3,500) ← `pending_facilitator`.
3. الميسّر يعتمد ← `pending_leader` ← ق.ع يعتمد (لا تنبيه تجاوز) ← `approved`، ويصل مفوّضي الصرف «حوّل العهدة».
4. م.م لديه رصيد 2,000: يحوّل **2,000** لقائد المجموعة بإيصال ← عهدة `active`، المتبقي 1,240 «دفعة مؤجّلة».
5. المستلم يرفع 4 نماذج؛ المراجع يقبل ويرفض بنداً بسبب «الكمية غير ظاهرة» ويفك حجزه؛ المستلم يرفع نموذجاً جديداً.
6. بعد إيداع جديد يحوّل م.م الـ1,240. 
7. المستلم يطلب الإغلاق ← المراجعة ← فائض 80 ← إيصال ← تأكيد ← إغلاق ← تُكمَل مهمة «الإغلاق المالي».
8. [حساب]: بند «الإغلاق المالي في الموعد» = 1 إن خلال 14 يوماً من نهاية الرحلة.
