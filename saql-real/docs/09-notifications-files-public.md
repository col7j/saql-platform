# 9. الإشعارات

## 9.1 المبادئ
- **داخل المنصة فقط** في النسخة الأولى (BR-801). الإيميل والشات مؤجلان؛ تبقى البنية جاهزة (`notification_policy.email_important`) ليحدد مسؤول التقنية لاحقاً ما يصل بالبريد.
- الإشعار صف في `notification` للمستلم الواحد (ليس بثاً)، بـ`link` يفتح الشاشة المناسبة، و`dedupe_key` يمنع التكرار (BR-802).
- **جرس** ثابت أعلى الشاشة بعدّاد غير المقروء + صفحة «الإشعارات» (قراءة واحد / الكل).
- الإشعار ≠ «المطلوب منك الآن»: الثاني **محسوب** من الحالة (`pendingActions`) ولا يُخزَّن؛ الأول حدث.

## 9.3 «المهم»
قائمة `importantNotifications` (الافتراضي: طلب ميزانية، رفض موافقة، فوات موعد، صرف عهدة، نشر التشكيل، غياب قائد، طلب عضوية لجنة) يملكها مسؤول التقنية؛ **لا تُرسل بالإيميل الآن** (سبب حذف علامة «وصلت بالبريد» A#108). عند ربط الإيميل: خدمة بريد معاملات (Resend/SES/Postmark)، قالب عربي RTL، رابط عميق، وإلغاء اشتراك لغير الحرج.

## 9.4 الجدولة والتذكيرات والمواعيد النهائية (جديد في الحقيقية)

الديمو لا يملك خادماً، فيولّد `schedule_started` و`survey_available` عند فتح الصفحة، ولا يولّد `deadline_*`. الحقيقية تحتاج مجدولاً (pg-boss على PostgreSQL، لا خدمة إضافية):

| المهمة | تكرار | الوظيفة |
|---|---|---|
| `formation.publish` | عند `publish_at` | قلب الحالة + إشعار + بدء أثر الظهور |
| `deadlines.scan` | كل 15 دقيقة | لكل (رحلة، نموذج) لم يُرفع: `deadline_near` قبل `reminderDaysBefore`(3) أيام و`deadline_passed` بعد الموعد؛ لقاء التركيز الذي مضى وقته ولم يُحضَّر؛ دفعات العقود |

|---|---|---|
| صورة | 10MB، تُضغط في المتصفح لضلع ≤ 2400px قبل الرفع | تحويل HEIC → JPEG عند الحاجة |

| فيديو | **رابط خارجي** (يوتيوب/درايف) افتراضياً؛ رفع مباشر حتى 200MB اختياري | تجنباً لتكلفة التخزين والبث |

| أسماء الملفات | تُعاد تسميتها في التخزين (`{uuid}.{ext}`) والأصل في `original_name` | |

## 10.3 التخزين
- **S3-compatible** (Cloudflare R2 / AWS S3 / Supabase Storage / MinIO) ببكت خاص `saql-private` لكل الملفات؛ بكت عام اختياري لأصول الموقع العام المنشورة فقط (شعار، صور أقسام، شعارات الجهات).
- مفاتيح `storage_key = {purpose}/{yyyy}/{uuid}`.
- `sha256` يحسبه **الخادم** أثناء الرفع (stream). المعاينة المصغّرة تُولَّد خادمياً (`thumb_key`).
- فحص البرمجيات الخبيثة: ClamAV أو خدمة فحص (اختياري المرحلة 10).
- النسخ الاحتياطي: تفعيل versioning + نسخة يومية للبكت.

## 10.4 الصلاحيات على الملف
الملف يرث صلاحية **الكيان الذي يحمله** (لا صلاحية مستقلة):

| الملف | يراه |
|---|---|
| مرفقات المالية | م.م والمفوّضون (`view_budget`/`review_invoices`/`disburse` حسب السياق) + ق.ع + **صاحب العهدة** لعهدته فقط |
| باركود/آيبان | صاحبه + `disburse` (وقت التحويل) + م.م |
| صور الملف الشخصي | كل المسجّلين (أو حسب سياسة: الإدارة + المجموعة) |
| مواد المكتبة | وفق `audience` وكشف الوقت (`revealed`) ونفس `canSeeMaterial` |
| ملف ختامي | المشارك + ميسّره + ق.ع |
| ملفات اللجان | أعضاء اللجنة + ق.ع |
| أصول الموقع العام | الجميع (بكت عام/عبر CDN) |

## 10.5 روابط التحميل المؤقتة
`GET /api/v1/files/{id}/url` يفحص الصلاحية ثم يعيد رابطاً موقّعاً (presigned) **صلاحيته 5 دقائق** بـ`Content-Disposition` مناسب؛ الرفع عبر presigned PUT بعد `POST /files` (يحجز الصف ويعيد الرابط) ثم `POST /files/{id}/complete` (يحسب sha256 ويتحقق الحجم والنوع). لا روابط ثابتة لملفات خاصة. كل تنزيل لمرفق مالي أو آيبان يُسجَّل في التدقيق.

# 11. الصفحات العامة

## 11.1 الموقع التعريفي (`/`)
- عام بلا تسجيل، **بلا نقاط وتفاصيلها**؛ الترتيب **بالأسماء فقط** بعد نشر التشكيل (قرار القرارات الأحدث، ويخالف نص التصور القديم)، وبلا أرقام جوال.
- المحتوى من الإعدادات: `site_content` (عنوان، كلمة تمييز، تعريف، بريد التواصل) + `site_section` بأربعة قوالب: **نص**، **صورة** (+تعليق)، **قائمة أشخاص** (مصدرها فريق العمل بلا أرقام، أو الخمسة الأوائل)، **جدول** (يدوي، أو المشاركون أبجدياً مع المجموعة، أو المجموعات وترتيبها).
- تحرير: ق.ع أو من فُوّض `edit_site` مؤقتاً (مسؤول الإعلامية مثلاً): إضافة، حذف، إخفاء، إعادة ترتيب. **بلا محرر مواقع حر.**
- زر الدخول يحيل إلى `/login`.
- التقنية: صفحة SSR/ISR مخزّنة مؤقتاً (revalidate عند الحفظ) لسرعة وSEO؛ `Cache-Control` عام.

## 11.2 رابط الداعم (`/supporter`)
رابط **واحد ثابت** يُرسل من البداية، يفتح بكلمة مرور لكل جهة.

### الدخول والحماية
| البند | التصميم |
|---|---|
| الهوية | كلمة المرور تحدد الجهة (قرار الديمو)؛ لتفادي مقارنة كل الهاشات نخزّن `password_lookup = HMAC(secret, password)` فريد ثم نتحقق بـArgon2id |
| الجلسة | كوكي HttpOnly `Secure SameSite=Lax` بـ`supporter_session` (8 ساعات) |
| التقييد | 5 خاطئة ⇒ قفل 15 دقيقة (**لكل IP/بصمة** + عدّاد عام احتياطي)، ويُحسب دخول جهة معطّلة محاولة خاطئة؛ تأخير ثابت للاستجابة |
| التعطيل | ق.ع يعطّل جهة دون غيرها؛ جلساتها تُبطل فوراً |
| تغيير الكلمة | ق.ع يسجّلها ويغيّرها؛ تظهر مرة واحدة عند الإنشاء؛ تُمنع المكررة |
| ما لا يُنشر | `X-Robots-Tag: noindex`, لا فهرسة؛ لا روابط خارجية في الصفحة تسرّب الـReferer (`Referrer-Policy: no-referrer`) |
| التوصية | إضافة **اسم/رمز الجهة** مع كلمة المرور (أو كلمة طويلة مولَّدة ≥ 12 حرفاً) لأن «كلمة المرور وحدها» تجعل كلمة ضعيفة = هوية (20 س-12) |

### المحتوى (بالترتيب)
1. شعارات الداعمين والشركاء فوق/تحت شعار البرنامج (ق.ع يحدد الترتيب والتصنيف: فوق/تحت، أفقي/عمودي، أساسي أولاً؛ **التصنيف لا يراه الزائر**؛ بلا شعار ⇒ اسم الجهة).
2. فكرة البرنامج ونبذة (`program_idea`).
3. فريق العمل: أسماء وصور ومناصب وأرقام (بموافقة ضمنية ضمن الشروط والأحكام).
4. المشاركون المتميزون: المراكز الخمسة الأولى.
5. المجموعات (وترتيبها) — بعد نشر التشكيل.
6. جدول المشاركين أبجدياً مع مجموعاتهم.
7. الرحلات (الحالات أدناه).
8. التعليقات.

### حالات الرحلة
| الحالة | الشرط | ما يظهر |
|---|---|---|
| **قبل** | غير منشورة أو لم تبدأ | بطاقة ضبابية بقفل، التاريخ، نوعها، (المنفِّذ بعد نشر التشكيل فقط)، نبذة من الوثيقة بعد رفعها |
| **يوم الرحلة** | بدأت ولم تنتهِ | الجدول الفعلي حياً (ما ثبّته المتابع) + عدد الحضور حتى الآن (استطلاع/تحديث كل 30–60ث؛ لا حاجة لـWebSocket) |
| **بانتظار الإغلاق** | انتهت ولم تُغلق | شارة «بانتظار الإغلاق» بلا محتوى |
| **بعد** | أُغلقت كاملاً واعتُمد تقريرها | التقرير العام، الصور، رابط الدرايف، التغريدات، عدد الحضور |

### التعليقات
زائر مسجَّل الدخول يعلّق باسم جهته (أو اسم يكتبه) ← `status = pending` (إعداد `trackingCommentsNeedReview`) ← يراجعها فريق العمل من «رابط الداعم» (`visible`/`hidden`) ← تظهر علناً. إشعار للإعلامية عند الورود. مكافحة السبام: حد طول، وحد معدل (3/ساعة/جلسة).

### ما لا يظهر أبداً
الترتيب بالنقاط وتفاصيلها · أي بيانات مالية · جوال/بريد/آيبان المشاركين · ملاحظات الميسّرين · الخطط الشخصية.

## 11.3 إدارة الرابط (داخلية: «رابط الداعم»)
ق.ع/فريق العمل: جهات الداعمين (إضافة/كلمة مرور/تعطيل/شعار/ترتيب)، حد المحاولات، فكرة البرنامج، ومراجعة التعليقات. (فريق العمل `isStaff` يدخل الشاشة في الديمو؛ تعديل الجهات للقائد العام وحده.)
