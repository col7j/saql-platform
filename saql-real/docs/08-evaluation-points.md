# 8. التقييم والنقاط

> المصدر: وثيقة القرارات (قسم «التقييم»)، `ASSUMPTIONS.md` 35–43، 139–145، 161–168، وكود `domain/points.ts` و`settings.ts` و`data/defaults.ts`. القاعدة الذهبية: **النقاط كسب فقط**.
> الهدف في الحقيقية: نفس النتائج بالضبط. يلزم اختبار مطابقة (golden/parity) يحسب `computeScores` على بيانات seed واحدة ويقارن (القسم 17).

## 8.1 الصورة العامة

```
الدرجة الكلية للمشارك = الفردي (من 50 + تميّز التقديم)  +  درجة مجموعته الجماعية (من 50)

الفردي  = Σ_{بند فردي مفعّل} ( 50 × حصة_البند × نسبة_البند ) + تميّز_التقديم
الجماعي = Σ_{رحلة} Σ_{بند جماعي مفعّل} ( نصيب_النوع × حصة_البند ÷ عدد رحلات المجموعة من النوع × نسبة_البند )
```
- **حصة البند** = `weight ÷ Σ weight` للبنود المفعّلة ذات الوزن >0 في نفس النطاق (فردي/جماعي) — فلا يلزم أن يبلغ مجموع الأوزان 100 (BR-602).
- **نصيب النوع** للجماعي = `split.group × groupTripSplit[type] ÷ (internal + external)` (افتراضي 50×40/100 = 20 للداخلية، 30 للخارجية).
- كل نسبة مقصوصة إلى [0,1] قبل الضرب، فلا قيمة سالبة ولا تتجاوز 1 (إلا نقاط التميّز الثابتة).
- **عمود الإعداد**: كل أرقام هذا القسم قيم افتراضية في `evaluation_item` و`setting` (الملحق ج) تُعدَّل بيد ق.ع ثم تُقفل.

## 8.3 الفردي

### 8.3.1 الحضور (`attendance`)
```
قيمة رحلة t:  لا سجل | غائب = 0 ;  متأخر = attendanceLateCredit (0.5) ;  مبكر | في الوقت = 1
الأنواع:
  focus      = عدد لقاءات مجموعته (held|closed) التي حضرها / عددها
  trip       = Σ قيمة(t) لرحلات (published ∧ started) / عددها
  tripSession= لقاءات الرحلة (بند تصنيفه requires_prep وله session وسُجِّل لها حضور) التي حضرها / عددها
نسبة الحضور = متوسط موزون بـ attendanceWeights {focus:40, trip:40, tripSession:20} للأنواع التي مقامها > 0 فقط
```
- الأنواع بلا فعاليات منعقدة تُسقَط من المتوسط (لا يخسر المشارك لفعالية لم تحدث، A#37).
- أحداث الرحلة المحسوبة تشمل **كل** الرحلات المنشورة التي بدأت (الرحلات عامة لكل المشاركين).
- غياب السجل = غياب.

### 8.3.2 التقديم (`presenting`)
```
evals = تقييمات الميسّر لكل لقاء قدّمه المشارك (كل منها {criterion → 1..5})
لكل معيار c: avg_c = متوسط تقييمات c عبر المرات ÷ 5
ratio = متوسط avg_c عبر المعايير            (مقصوص 0..1)
extra = (n − 1) × presentingExtraBonus       (نقاط ثابتة، افتراضياً 2)
points = maxPoints × ratio + extra            -- يجوز تجاوز سقف البند بـextra
```
- لا تقديم ← 0 («لم يقدّم بعد، لا خصم»).
- `presentingRevealAfterEnd=true`: لا تُحسب نتيجة التقديم في الترتيب حتى **بعد** `program.end_date` (تظهر «قدّم n مرة · النتيجة بعد النهاية»).
- مثال: قدّم 3 مرات، متوسط المعايير 80%، سقف البند 5 نقاط: `5×0.8 + 2×2 = 8.0`.

### 8.3.3 تقييم القائد العام (`leader_eval`)
مرة واحدة لكل مشارك ببنود `leader_eval_item` (6 افتراضياً، مجموع الحد الأعلى 100): `ratio = Σ min(max_i, score_i) ÷ Σ max_i`. بلا تقييم ← 0.

### 8.3.4 الخطة الشخصية (`personal_plan`)
```
meetings = min(1, اللقاءات الفردية المنجزة ÷ individualMeetingsPerParticipant)   -- الهدف 4
steps    = (منجزة + 0.5 × (بدأت + متحدية)) ÷ إجمالي الخطوات                          -- 0 إن لا خطوات
ratio    = (50×meetings + 50×steps) ÷ 100        (الوزنان فرعيان في subitems)
```

## 8.4 الجماعي (الرحلات فقط)

لكل مجموعة g ونوع T ∈ {internal, external}: الرحلات `trips(g,T)`. لكل رحلة `t` وبند `i`:
```
maxPoints(t,i) = نصيب_النوع(T) × حصة(i) ÷ max(1, |trips(g,T)|)
points(t,i)    = maxPoints × clamp01(ratio(t,i))
group.total    = Σ points
```
الأعمدة `max` للنوع ثابتة حتى لو لم تكتمل الرحلات.

### 8.4.1 `trip_auto` (الأوزان الفرعية 15/15/15/10/15/10/20)
| فرعي | القيمة |
|---|---|
| `document_on_time` · `schedule_on_time` · `budget_on_time` | تاريخ الرفع ≤ **التبكير** ⇒ 1 · ≤ **النهائي** ⇒ `deadlineFinalCredit` (0.5) · بعده أو بلا رفع ⇒ 0. التبكير = `min(بداية − أيام التبكير(30/15/15), النهائي)`. |
| `trip_closed` | `closed_at ≤ نهاية الرحلة + tripCloseDaysAfter(14)` ⇒ 1 · بعدها ⇒ 0 · لم يحن الموعد ولم تُغلق ⇒ يُحسب 0 مؤقتاً |
| `finance_closed` | آخر عهدة أُقفلت للرحلة (وكلها مقفلة) `closed_at ≤ نهاية + financeCloseDaysAfter(14)` ⇒ 1 وإلا 0 · بلا عهدة ⇒ 0 |
| `report_on_time` | رُفع التقرير الختامي ≤ نهاية + `finalReportDaysAfter(7)` ⇒ 1 وإلا 0 |
| `schedule_adherence` | (عدد بنود الجدول الفعلي التي سُجِّل لها `followed ≠ none`) ÷ (عدد المسجّل) · لا سجل ⇒ 0 |
`ratio = Σ(وزن_فرعي × قيمة) ÷ Σ أوزان الفرعيات` (القيم المعلّقة تحسب صفراً — كسب فقط).
> ملاحظة تنفيذية: الدالة `withinDeadline` في الديمو تقارن نصوص ISO؛ في الحقيقية قارن `timestamptz` بمنطقة البرنامج.

### 8.4.2 `finance_manual`
`ratio = Σ_{k} score_k ÷ (عدد بنود المالية × 5)` من `trip_finance_rating`. لا تقييم ← 0.

### 8.4.3 `staff_rating`
`ratio = avg(trip_staff_rating.score) ÷ 10`. لا تقييم ← 0.

## 8.5 نقاط إدارة المواد الإثرائية

`enrichment = (عدد مواد رفعها عضو الإدارة: audience=all ∧ points_requested ∧ points_status=approved) × enrichmentPointsPerMaterial`، وإن كان بند `enrichment` مفعّلاً. تُعرض لفريق العمل في «نقاط الإدارة» ولا تدخل ترتيب المشاركين.

## 8.6 الدفتر (ledger) والترتيب

### تسجيل النقاط (ما يخالف الديمو)
الديمو يحسب كل شيء حياً عند القراءة ويولّد `log` مؤقتاً. المنصة الحقيقية تخزّن **دفتراً**:

| العنصر | التصميم |
|---|---|
| `points_run` | تشغيل حساب كامل: `eval_config_version`، السبب، الحالة. يشتغل: (أ) عند الأحداث المؤثرة (مُجمَّعة بتأخير 5–10 ث debounce)، (ب) ليلياً، (ج) يدوياً بعد فتح قفل التقييم وحفظه. |
| `points_entry` | سطر لكل (مصدر، شخص/مجموعة، بند، رحلة) بـ`source_key` حتمي (`ind:{person}:{item}` · `grp:{group}:{trip}:{item}`) و`points ≥ 0` ونسبة وتفصيل نصي. مصدرها تلقائي دائماً (`auto`) لأن اليدوي لا يُسجَّل نقاطاً بل تقييماً (مدخلات). |
| القراءة | `v_points_current` = آخر تشغيل ناجح. صفحة الترتيب وسجل النقاط وتفصيل «مستواي» تقرأ منه. |
| الاحتفاظ | تشغيلات ليلية تُحفظ دائماً (منحنى الترتيب)؛ التشغيلات داخل اليوم 7 أيام. |
| التطابق | دالة الحساب واحدة (حزمة `packages/domain/points`) تُستدعى من المهمة، وتُختبر ضد نتائج الديمو. |

**الأحداث التي تُطلق إعادة الحساب:** حفظ حضور · إغلاق/انعقاد لقاء تركيز · تقييم مقدّم · تقييم ق.ع · لقاء فردي منجز · حفظ متابعة خطوة/تغيّر حالتها · رفع/اعتماد نموذج رحلة · اعتماد/إرسال ميزانية · إغلاق/تسوية عهدة · تثبيت جدول فعلي · تقييم فريق/مالية · إغلاق رحلة · حفظ التقييم (تغيّر الأوزان) · اعتماد نقاط مادة.

### وزن كل بند كإعداد
`evaluation_item.weight` + `subitem.weight` + الإعدادات المفردة (`eval.*`). تغييرها يتم من «التقييم والأوزان»، ثم **حفظ + قفل** (يلتقط `evaluation_config_version` ويُطلق `points_run`). فتح القفل: م.ت وحده بسبب يُسجَّل ويُشعَر ق.ع. عند التعديل يعيد الحساب كل النقاط بالقيم الجديدة (الماضي يُعاد تفسيره؛ لا «نقاط مجمّدة بقيم قديمة» — قرار يحتاج تأكيداً، س-17).

### الترتيب
```
rank_person = ترتيب تنازلي بـ total = individual + groupShare   (الديمو: الفهرس في القائمة المرتبة، فالتعادل ترتيبه بحسب ثبات الفرز)
rank_group  = ترتيب تنازلي بـ group.total
```
- **المقترح في الحقيقية** (غير محدد بالديمو، س-05): ترتيب المنافسة القياسي (التعادل بنفس المركز، والتالي يقفز)، وكسر التعادل بالأعلى فردياً ثم الأبجدي.
- «كم ينقصني لأدخل الخمسة الأوائل» = `top5[4].total − mine.total + 0.01` إن كان خارجها.
- يظهر الترتيب بالأسماء بعد نشر التشكيل (BR-614).

### سجل النقاط للمستخدم
المشارك: ما يخصه وما يخص مجموعته؛ فريق العمل: الكل.

## 8.7 أمثلة اختبار

| الحالة | المتوقع |
|---|---|
| لا فعاليات منعقدة | نسبة الحضور 0 والمشارك لا يخسر شيئاً |
| غياب كامل | نقاط الحضور 0، والإجمالي لا ينقص عن نقاط بنود أخرى |
| متأخر عن رحلة واحدة من 3، الباقي حضور مبكر | trip value = (1+1+0.5)/3 = 0.8333 |

| وزن بند = 0 | البند خارج الحساب |
| عضو مجموعة آخر غير منفِّذ لرحلة ما | يحصل على إجمالي مجموعته (BR-606) ولو لم يحضر |
